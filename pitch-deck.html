How It Works

One control plane. Local CLIs. Shared memory.

     Humans                          Agents
     ──────                          ──────
 ┌───────────────┐               ┌───────────────┐
 │ Web Dashboard │               │  Claude Code  │
 │   (Next.js)   │               │    (BYO CLI)  │
 └───────┬───────┘               └───────┬───────┘
         │ REST + SSE                    │ MCP tools
         ▼                               ▼
   ┌─────────────────────────────────────────────┐
   │            @beevibe/api  · control plane    │
   └─────────┬──────────────────────────┬────────┘
             │ SQL                      │ WSS push
             ▼                          ▼
   ┌────────────────────┐    ┌────────────────────┐
   │  Postgres + pgvector│    │  beevibe-daemon    │
   │  shared state,     │    │  spawns the local  │
   │  mesh, memory      │    │  CLI per session   │
   └────────────────────┘    └────────────────────┘
  • API — control plane: REST, SSE, MCP, WSS, daemon orchestration.
  • Postgres + pgvector — shared state, mesh, memory, sessions.
  • Daemon — runs on your laptop, claims sessions, spawns the CLI.
  • Scheduler — server-side fallback when a daemon is offline, plus orphan reaping.
Core Concepts

A small vocabulary, composed.

Workspace
The company-level place where people, agents, tasks, memory, and review live together.
Agent
A persistent domain expert with a role, hierarchy level, memory, API key, and preferred runtime.
Task
A unit of team work assigned to a person or agent. Tasks spawn children and move through review.
Mesh
The agent-to-agent layer for asking the right teammate, negotiating, responding, and escalating.
Memory
Durable per-agent core memory blocks + vector-searchable facts that compound across team work.
Runtime
A registered (daemon, CLI) pair — usually a user’s local claude binary.
Daemon
A local process that claims sessions and spawns CLI runs on a user’s machine.
BYO CLI

Your tools. Your files. Your tokens.

Beevibe doesn’t take your codebase hostage in a hosted sandbox. Every agent run happens on a developer’s own machine, through their own CLI, with their own file system and API keys.

Local file access User-owned API keys Real dev environment No data exfiltration 
# Install the daemon on your laptop
brew install beevibe-ai/tap/beevibe-daemon

# Point it at your workspace
beevibe-daemon setup \
  --api  http://localhost:3000 \
  --user-token bv_u_…

beevibe-daemon start
# → claims sessions, spawns Claude Code locally

Get Started

Spin up Beevibe in two minutes.

Option A · Local Docker

git clone https://github.com/beevibe-ai/beevibe.git
cd beevibe

ANTHROPIC_API_KEY=sk-ant-… \
OPENAI_API_KEY=sk-… \
docker compose -f docker-compose.quickstart.yml \
  up -d --build

Then open http://localhost:3030.

Option B · One-click Railway

Provisions Postgres, api, scheduler, and web in a single click. Drop in your ANTHROPIC_API_KEY and you’re live.

  • Install beevibe-daemon on each developer’s laptop.
  • Register agents from the dashboard.
  • Watch your team’s shared brain start to compound.
